# デザインドキュメント

デザインに一貫性をもたせるためのガイドライン。記録画面の新規実装・改善では、[ごはん記録のデザイン改善（PR #49）](https://github.com/cateiru/canshi/pull/49)で採用した、余白・淡い背景・アイコンを使うデザインを基準とする。

既存の共通コンポーネントには従来の枠線や角丸が残っている。画面を改善するときに本書の方針を適用し、適用済みの画面と既存画面を混同しない。

## デザインコンセプト

- 「猫」をテーマにしたデザイン
- 基本的にモノトーンのテーマとしてベース背景色＋文字色で構成する
- アイコンなど一部のものに対してはアクセント色を使用する
- 商品名や記録の数値をひと目で拾え、日々の入力を迷わず行えることを重視する

## デザイン原則

- 余白と背景で情報をまとめる
  - 記録カードやフォームの商品グループは、淡い背景と余白で区切る
  - 外枠・商品間の罫線・内側の枠を重ねない。枠線は入力欄や状態の識別など、意味がある箇所に使う
  - 通常の入力欄には淡い実線を使い、フォーカスとエラーは明確に表示する
- 情報に強弱を付ける
  - 商品名・重要な数値を強調し、補足情報や単位は控えめにする
  - 重複する見出しやラベルを減らす。入力項目の意味や推定値であることは省略しない
- 用途に応じた角丸
  - ボタン・入力欄は 8px、合計表示は 12px、記録カード・フォームの商品グループは 16px を目安とする
  - 商品画像は 8〜10px。既存の `--radius-base: 4px` は共通コンポーネントの基礎値として残っているが、すべての要素を 4px に限定しない
- 猫らしさはアクセントとして使う
  - 猫耳を模した装飾は CatEarFrame など必要な箇所に使い、各記録カードや入力欄には必須としない
  - 猫耳を使う場合は `___^__^___` のような輪郭を `--color-ink` で描き、内側は `--color-bg` にする

## デザイントークン

- `--color-bg`: #fff
- `--color-ink`: #2e3142
- `--color-accent`: #ec995a
- `--color-success`: #52b355
- `--color-warning`: #f2d14b
- `--color-error`: #f25c4b
- `--color-info`: #4f87db

### 背景と境界の使い分け

ごはん記録では、既存の色トークンを `color-mix()` で調整して使う。以下は用途別の値であり、新しいグローバルトークンは追加していない。

| 用途 | 色・背景 |
| --- | --- |
| 記録カード・フォームの商品グループ・補助ボタン | `color-mix(in srgb, var(--color-ink) 4%, var(--color-bg))` |
| 合計表示・入力欄 | `var(--color-bg)` |
| 通常の入力欄の枠線 | `color-mix(in srgb, var(--color-ink) 20%, var(--color-bg))` |
| プリセット・最近使った商品のボタン | `color-mix(in srgb, var(--color-accent) 14%, var(--color-bg))` |
| アイコンボタンの hover 背景 | `color-mix(in srgb, var(--color-ink) 7%, var(--color-bg))` |
| 与えた量・残した量などの補足文字 | `color-mix(in srgb, var(--color-ink) 78%, var(--color-bg))` |

背景を淡くしても、商品名・数値・操作ラベルには読みやすい濃さを確保する。主操作のボタンは `--color-ink` の背景と `--color-bg` の文字で強調する。

## タイポグラフィ

Web フォントは読み込まず、システムフォントのみを使用する。

```css
--font-sans:
  system-ui, -apple-system, "Hiragino Sans", "Yu Gothic UI", "Yu Gothic",
  "Noto Sans JP", sans-serif;
```

| トークン | サイズ | ウェイト | 用途 |
| --- | --- | --- | --- |
| `--text-xl` | 24px | 700 | ページタイトル・合計などの重要な数値 |
| `--text-lg` | 18px | 700 | モーダル見出し・セクション見出し |
| `--text-md` | 15px | 700 | 商品名・記録日時・主操作のラベル |
| `--text-sm` | 13px | 400 / 700 | 本文・単位・入力ラベル・小見出し |
| `--text-xs` | 11px | 400 / 700 | 推定などの注記・バッジ |
| `--text-input` | 16px | 400 | 入力欄・商品選択欄 |

- `line-height` は本文 1.7、見出し 1.4 を基本とする
- 数量や日時には `font-variant-numeric: tabular-nums` を使い、数字を比較しやすくする
- 数値と単位は同じ強さにせず、合計は 24px、単位は 13px を目安にベースラインを揃える
- 入力文字は `--text-input` を使い、狭い画面でも小さくしない

## スペーシング

4px を基数としたスケールを使用する。

| トークン    | 値     |
| ----------- | ------ |
| `--space-1` | `4px`  |
| `--space-2` | `8px`  |
| `--space-3` | `12px` |
| `--space-4` | `16px` |
| `--space-6` | `24px` |
| `--space-8` | `32px` |

記録画面のコンテンツ幅は最大 800px、左右の余白は 16px を基準とする。記録間・フォームの大きなまとまりの間は 24px、商品間や入力項目の間は 8〜16px とし、関連する情報ほど近づける。

## アイコンと操作

- Tabler Icons（`react-icons/tb`）を使い、線画の見た目を揃える
- 編集は `TbPencil`、記録の削除は `TbTrash`、フォームの商品行の削除は `TbX`、追加は `TbPlus` を使う
- 編集・削除など意味が伝わりやすい補助操作はアイコンのみで表示できる。「記録する」「更新する」「商品を追加する」などの主な操作には短いラベルを残す
- アイコンのみの操作には `aria-label` で操作名を付ける。繰り返す商品行では「商品 2を削除」のように対象も伝える
- 装飾アイコンには `aria-hidden="true"` を付ける。アイコンのみの操作にはポインターで確認できる補足も付けるが、`title` だけを操作名の代わりにしない
- アイコン自体は 16〜20px を目安とし、ボタンの操作領域は最低 44×44px を確保する
- 保存済みの記録を削除するときは、確認ダイアログとキャンセル操作を用意する

## 記録一覧

1回の記録をひとつのカードにまとめ、日時・内容・合計の順に読めるようにする。ごはん記録では次の構成を採用する。

1. 上部に時計アイコンと日時、右側に編集・削除のアイコンを置く
2. 商品画像と商品名を横に並べ、その下に与えた量・残した量をコンパクトに表示する。「商品」というラベルは繰り返さない
3. 下部の白い背景に、食べた量とカロリーの合計を2列で表示する。短いラベルとアイコンを添え、推定値には「（推定）」を残す

商品画像は 48×48px を目安とし、未登録なら共通の FoodProductImage のアイコン表示を使う。一覧の商品名は折り返して全文を確認できるようにする。記録がない場合も、淡い背景・アイコン・短い案内・最初の記録へのボタンでまとめる。

## 記録フォーム

- 日時、プリセット・最近使った商品、商品と数量、追加、保存の順に並べる
- 商品グループは枠線のない `fieldset` とし、アクセシブルな名前を付ける。「商品 1」という見出しと「商品」という入力ラベルを二重に表示しない
- 商品画像・選択欄・商品行の削除を同じ行に置き、与えた量・残した量はその下に2列で並べる
- 日付・時刻・数量などの入力ラベルと単位を残す。文字を減らすために入力の意味をアイコンだけで表現しない
- 入力欄と保存ボタンの高さは最低 48px。入力欄は白い背景と淡い枠線で識別できるようにする
- プリセットは現在の商品行を置き換え、最近使った商品は行を追加する。追加用の選択肢にはプラスアイコンを添える
- エラーは該当する入力欄の近くに文章で表示し、`--color-error` の枠線も付ける。保存中は主操作を無効化し、「保存中...」と表示する

## 狭い画面への対応

- 日付と時刻、与えた量と残した量の2列には `minmax(0, 1fr)` を使い、各項目に `min-width: 0` を設定する
- 480px 以下ではカードの内側余白を 24px から 16px に縮める。文字サイズや操作領域を削って収めない
- プリセットや最近使った商品の選択肢は横スクロールにし、次の選択肢があることを見えるようにする。キーボードのフォーカスリングが切れない余白も確保する
- 長い商品名は選択ボタン内では省略表示し、選択肢を開くと全文を確認できるようにする。画像・操作アイコンは縮めない
- 画面全体には横スクロールを発生させず、ページ見出しや記録の操作列は必要に応じて折り返す
- PC幅に加えて 390px・320px でも、長い名前、複数商品、入力エラー、アイコン操作を確認する

## モーション

- インタラクティブな要素（ボタン・入力欄など）には hover・focus 時の状態変化を必ず付ける
- `--transition-base` を基本のトランジション速度として使用する
- ボタンは hover で `opacity: 0.85`、押下時（active）は `translateY(1px)` でわずかに沈み込ませる
- フォーカスリングはマウスクリックでは出さず、キーボード操作時のみ `:focus-visible` で表示する
- フォーカスリングは `--focus-ring-width`（太さ）・`--focus-ring-offset`（要素との余白）・`--color-accent`（色）で統一する
- 入力欄の通常の枠線とフォーカスリングは分けて扱う。共通の FormField・Textarea は hover 時に `--color-info` を使うが、ごはん記録のように淡い枠線を保つ場合も、キーボード操作時にはアクセント色のフォーカスリングを表示する。エラー状態は hover 時も `--color-error` を維持する
- 入力欄以外のインタラクティブ要素（Checkbox・Radio・Select・Tabs など）の hover・選択時の強調色は `--color-accent` を使う
- `prefers-reduced-motion: reduce` の環境では `--transition-base` を `0ms` にしてトランジションを無効化する（`globals.css` でグローバルに対応済み）

## バッジ

バッジは文字色・背景色は変えず、輪郭の色のみで表現する

```css
.badge {
  border: 1px solid var(--color-info);
  color: var(--color-ink);
  background-color: var(--color-bg);
}
```

## Alert

Alert はバッジと異なり、状態色（info・success・warning・error）で背景・枠線を塗りつぶし、文字色は `--color-bg` にする

```css
.alert {
  border: 1px solid var(--color-info);
  color: var(--color-bg);
  background-color: var(--color-info);
}
```

## コンポーネントの実装方針

インタラクティブな UI コンポーネントは [react-aria-components](https://react-spectrum.adobe.com/react-aria/) をベースに実装する。

- Button・FormField・Textarea・Select・Checkbox・Radio・Tabs・Modal・Heading・Toast は react-aria-components のコンポーネントをラップして実装する
- 状態のスタイリングは `:hover` や `:disabled` などの擬似クラスではなく、react-aria-components が付与する `data-hovered` / `data-selected` / `data-focus-visible` などの `data-*` 属性セレクタを基本とする
- react-aria-components の各コンポーネントは `"use client"` 境界を要求するため、これらをラップするコンポーネントのファイルにも `"use client"` を付与する
- Badge・Card・CatEarFrame・Alert は react-aria-components に対応するプリミティブが存在しない純粋な装飾・表示用コンポーネントのため、素の HTML 要素のまま実装する（Card の見出しのみ、共通の Heading コンポーネントを利用する）
- 枠線のない記録表示には `article`・見出し・`time`・`dl` などを使い、内容の構造を保つ。既存の Card を使うためだけに装飾の枠線を追加しない
- 画面固有の背景・角丸・余白は CSS Modules で指定する。共通コンポーネントを拡張するときは、既存画面への影響を確認する
- Toast はページ内の 1 箇所（ルートレイアウト）にのみ `ToastRegionRoot` をマウントし、`addToast()` で通知を積む

コンポーネントの一覧・動作は `/dev/components`（開発時のみ表示）で確認できる。
