# 04. デザインシステム実装

## 目的

`docs/idea/design.md` のデザインガイドラインをコードに落とし込み、以降の機能 PR が共通利用できる基盤コンポーネント・トークンを整備する。

## スコープ

- デザイントークンの実装（色・タイポグラフィ・スペーシング）を CSS カスタムプロパティとして定義
- 猫耳を模した装飾（`___^__^___` のボーダー表現）を持つ共通コンテナコンポーネント
- ボタン・カード・バッジ・モーダル・フォーム部品など、以降の機能 PR で共通利用する最小限の UI コンポーネント
- システムフォントのみを使うグローバルスタイルの設定
- Storybook 等のカタログツールは導入せず、コンポーネントごとの簡易なプレビューページ（開発時のみ表示するルート）で代替する

## 対象外

- 各機能固有の画面・フォーム（`05` 以降）
- PWA 対応（第2段階）

## 依存 PR

- `01`（プロジェクト基盤構築）

## 変更・追加内容

- `src/styles/tokens.css`（色・フォント・スペーシングのカスタムプロパティ）
- `src/styles/globals.css`
- `src/components/ui/`（Button、Card、Badge、Modal、FormField 等）
- `src/components/ui/CatEarFrame`（猫耳装飾コンポーネント）
- 開発確認用のプレビュールート（例：`/_dev/components`）

## DB マイグレーション

なし

## 受け入れ条件

- デザイントークン（`docs/idea/design.md` に定義された値）がすべて CSS カスタムプロパティとして参照できる
- 猫耳装飾・ソリッドな枠線・`border-radius: 4px` の原則が共通コンポーネントに反映されている
- バッジが「輪郭色のみで表現する」仕様どおりに実装されている
- 主要コンポーネントに対する Vitest（スナップショットもしくはレンダリングテスト）が存在する
