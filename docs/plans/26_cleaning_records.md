# 26. 掃除記録機能

## 目的

猫砂・おしっこシートなど掃除対象ごとに頻度を設定し、実施日を記録して次回の掃除タイミングを把握できるようにする。`28` の通知（次の掃除タイミング）の判定元になる。

## スコープ

- 掃除対象の設定（`cleaning_targets`）
  - 名前、頻度（日数）、有効・無効の登録・編集・削除
  - 猫ごとに管理する（`03` の規約に従い `cat_id` を持つ。同居猫で共用するトイレも、通知を猫単位で扱うため猫ごとに登録する）
  - 初回利用時の導線として「猫砂」「おしっこシート」をワンタップで追加できるプリセットを用意する
- 掃除の実施記録（`cleaning_records`）
  - 掃除対象、実施日時、備考の記録
  - 掃除対象の一覧から「今すぐ掃除した」をワンタップで記録できる
- 掃除対象ごとの「前回の実施日」「次回の予定日（前回 + 頻度）」「期限超過」の表示
- 記録の一覧・編集・削除
- 猫詳細ページの記録導線（`RECORD_NAV_ITEMS`）への追加
- タイムライン（`14`）への追加（`03` の発生日時列の対応表に `cleaning_records.performed_at` を追加する）

## 対象外

- 掃除タイミングの通知（`28`・`31`）
- 掃除用品の在庫管理

- `src/features/cats/recordNav.ts`・`src/features/timeline/` の更新
- `src/db/README.md` の発生日時列の対応表の更新

## DB マイグレーション

- `cleaning_targets` テーブルを新規作成
  - `id`、`cat_id`、`name`、`frequency_days`、`is_active`、`sort_order`、`created_at`、`updated_at`
- `cleaning_records` テーブルを新規作成
  - `id`、`cat_id`、`cleaning_target_id`、`performed_at`、`memo`、`created_at`、`updated_at`
  - `cat_id` は `cleaning_target_id` 経由でも解決できるが、`12` の `medication_doses` と同じ理由（`03` の規約とタイムライン集約の統一）で保持する

## 受け入れ条件

- 掃除対象の登録・編集・削除と頻度の設定ができる
- 掃除の実施記録の登録・編集・削除・一覧ができ、ワンタップで記録できる
- 掃除対象ごとに前回の実施日・次回の予定日・期限超過が表示される
- タイムラインに掃除記録が表示され、種類で絞り込める
- 次回予定日・期限超過の計算ロジックに Vitest の単体テストがある
