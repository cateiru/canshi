# 16. 第2段階 概要

MVP（`01`〜`15`）完了後に着手する機能の方向性のみを記載する。PR 単位への詳細分割は別途行う。

## 対象機能

- 写真・動画のアップロード
  - `media_assets` テーブルは `03` で用意済みのため、R2 へのアップロード・EXIF 削除・サムネイル生成・Cloudflare Workers 経由の配信（Cloudflare Access によるアクセス確認後）を実装する
  - 対象は、うんち・嘔吐・症状・服薬（処方箋・薬袋）・通院（診療明細）・愛猫の体・ごはん商品（`media_assets.cat_id` は nullable のため、猫に紐付かないごはん商品の画像も同じ仕組みで扱える）
  - アップロードサイズ・保存容量の上限設定
  - 記録削除時の関連画像・動画の削除
- 水の記録
  - 測定方法、給水量、残量、こぼれ・水交換の有無
  - 給水量と残量からの推定飲水量の計算
  - 主観評価（多い・いつも通り・少ない）
- シャンプー記録
  - 実施日の記録
- 掃除記録
  - 掃除対象・頻度の設定と実施日の記録
- PWA 対応
- Web Push 通知
  - 誕生日・月齢・年齢の節目、シャンプー経過月数、体重測定の提案、掃除タイミングなどの通知
  - 通知時刻・タイムゾーンの設定、既読・重複防止、完了・延期・無視、通知ごとの有効・無効
  - Web Push 非対応環境向けの通知センター表示

## 想定される分割方針

- 画像アップロード基盤（R2 連携・EXIF 削除・サムネイル生成・配信）を先に 1 PR として独立させ、各記録への添付 UI は記録種別ごとに小さい PR へ分割する
- 通知は「通知条件の判定ロジック」「Web Push 送信基盤（Cloudflare Workflows のスケジュール実行）」「通知センター UI」「記録種別ごとの通知設定 UI」に分割する
- 水・シャンプー・掃除はそれぞれ独立した機能 PR とし、MVP の記録機能（`08`〜`13`）と同じ構成に従う

## 未決定事項（着手前に確認）

- 画像・動画の保存容量上限、1 ファイルあたりのサイズ上限の具体値
- サムネイル生成をどこで行うか（Workers 上か、Workflows によるバッチ処理か）
