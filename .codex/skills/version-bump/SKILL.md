# バージョンアップ

このリポジトリでは `package.json` の `version` と
`src/features/release-notes/release-notes.json` の各エントリの `version` は
常に一致させる（詳細な追記手順は [`AGENTS.md`](../../../AGENTS.md) の
「リリースノートの記載」を参照）。このスキルはその一致した値を
**どれだけ上げるか**を判断するためのもの。

## 上げ幅の判断基準

- **パッチ**（`x.y.Z` を上げる）: 文言修正、表記ゆれ、余白・色・アイコンなどの
  スタイル調整、既存機能の細かい不具合修正など、操作の骨格を変えない小さな変更。
- **マイナー**（`x.Y.0` に上げる）: 新機能の追加、既存機能への中規模な仕様変更
  （新しい入力項目・画面・絞り込み条件の追加など）。
- **メジャー**（`X.0.0` に上げる）: 使わない。**ユーザーが明示的に「メジャー
  バージョンを上げて」と指示した場合のみ**上げる。

- メジャーバージョンは実装内容の大小に関わらず自分の判断だけでは絶対に上げない。ブランドとしてのバージョンであり、上げるかどうかはユーザーが決める。
- パッチかマイナーか迷う場合は、安全側に倒してパッチとして扱う。

## 上げ方（どこを書き換えるか）

1. `package.json` の `"version"` を、上記の判断基準で決めた値に更新する。
2. `src/features/release-notes/release-notes.json` の配列末尾に、
   `src/features/release-notes/schema.ts` の `releaseNoteSchema` に従ったエントリを追加する。
   - `version` は 1. と必ず同じ値にする。
   - 手順・各フィールドの詳細は [`AGENTS.md`](../../../AGENTS.md) の
     「リリースノートの記載」を参照する。
3. `pnpm test` を実行し、`src/features/release-notes/data.test.ts` が通ることを確認する。

## 適用単位

- **1 PR = 1 回のバージョンアップ = 1 件のリリースノートエントリ。**
  同じ PR の中で追記や修正を重ねて複数回バージョンを動かした場合も、
  最終的な差分は 1 回のインクリメント・1 件のエントリにまとめる。
- ユーザーへの影響がない変更（内部リファクタリング、テストのみの変更、
  表示専用ページの追加など）は、リリースノートと同様にバージョンも上げない。
